# Шаблон сбора фактов по курортам

Файл `resort_data_collection_template.csv` — рабочая таблица со всеми 32 строками исходного списка ТЗ; сейчас активны 30 курортов, КолаСпортЛэнд и Гладенькая помечены как исключённые по сообщению пользователя. Сейчас заполнены только ID, название и регион из реестра. Примерные значения из учебного пакета не переносились.

## Правила заполнения

- Не записывать значение без URL источника и даты проверки.
- По договорённости для прототипа берём приблизительную геолокацию самого курорта или курортного посёлка; точные точки склонов не собираем. Проверяем совпадение названия и региона, сохраняем URL источника и помечаем координаты как приблизительные. Если геокодер находит одноимённое место в другом регионе, такой результат не используем.
- Официальные страницы курорта — основной источник для числа/длины трасс, уровня трасс, перепада высот и типов подъёмников.
- OpenStreetMap/Overpass — независимый дополнительный источник для пространственных объектов. Его сегменты нельзя считать официальным числом трасс без дедупликации и проверки геометрии.
- Пустое значение означает «не собрано», а не ноль.
- `verification_status`: `not_collected`, `candidate`, `verified`, `conflict`, `unavailable`.
- `coordinate_status`: `not_verified`, `approximate_candidate`, `verified`.
- `activity_tags` хранит подтверждённые виды катания/активности; формат прототипа — значения через `|`.
- Число подъёмников и километраж трасс собираются только при наличии ясного источника и методики. Километраж — справочная характеристика: он не участвует в ранжировании курортов.

## Результат пилота OSM для R001

Overpass API принял запрос по первой геокодированной точке Роза Хутор и радиусу 6 км. Получено 540 элементов OSM, включая объекты с тегами трасс, подъёмников и станций. Это подтверждает, что API позволяет исследовать покрытие источника, но не подтверждает точную координату, полноту данных или официальное число трасс. Сырой ответ, запрос и время получения сохранены в `data/raw/osm_pilots/R001_overpass_pilot.json`.

Точные точки и границы склонов не нужны для прототипа. Для найденных совпадений используем приблизительную точку курорта/посёлка; неоднозначные и ненайденные названия нужно искать по региону или через другой открытый источник. Публичный Nominatim не используем для массового регулярного геокодирования.

В текущем проходе геокодер дал 11 кандидатов с подходящими названием и регионом, плюс точку Роза Хутор из пилотного OSM-поиска. Затем пользователь предоставил ссылки Яндекс.Карт с параметром `ll` для остальных действующих курортов. Все 30 активных строк теперь имеют приблизительные координаты; две исключённые строки оставлены в реестре с причиной исключения. Кандидат в геокодере не считается автоматически подтверждённым курортом. Сводка: data/reference/geocoding_candidates_summary.csv.

## Последовательная проверка остальных курортов

Первичный проход выполнен по всем строкам действующего реестра R001–R032; исключённые R015 «КолаСпортЛэнд» и R032 «Гладенькая» оставлены исключёнными согласно решениям пользователя. Источники и факты из прохода заносятся в `data/reference/resort_source_facts.csv`. Все строки, у которых источники требуют сверки, имеют статус `candidate`; пустые поля не означают нулевое значение.

Основные вопросы, оставленные для сверки по важным для рейтинга данным:
- Уровни сложности трасс: для большинства курортов публичные источники не дают надёжной разбивки трасс по уровням, а сами классификации могут различаться. Для ранжирования по уровню катания нужен источник по каждому курорту и единая схема нормализации.
- Активности: нужно подтверждать наличие конкретных подходящих вариантов (трассовое катание, фрирайд, фристайл/сноупарк); временные и сезонные активности следует помечать отдельно.
- Чегет и Эльбрус — соседние, но самостоятельные зоны катания; данные и активности нельзя автоматически объединять.
- Для Мамисона источники расходятся по текущей зоне катания (ранние 14 км и нынешние «19 снежных километров»); километраж здесь остаётся справочным и не влияет на рейтинг.
- Для Аджигардака, Завьялихи и Абзаково пользователь подтвердил, что предоставленные карты взяты с сайтов самих курортов. По картам занесены уровни сложности и отмеченные активности; статус этих отдельных фактов — `source_checked`. У Аджигардака схема относится к сезону 2019/20, у Завьялихи и Абзаково дата на изображениях не видна. Актуальность карт для текущего сезона требует проверки. По Мраткино найдено описание на архивной копии официальной страницы; актуальность для текущего сезона ещё нужно проверить. По Морозной горе схема, предоставленная пользователем, принята как проверенная для прототипа по составу объектов; на ней нет легенды сложности, поэтому уровни берутся из имеющегося текстового описания и могут быть уточнены в итоговом проекте.

Общий километраж, число трасс и число подъёмников не являются обязательными данными для рейтинга. Если они опубликованы надёжным источником, их можно показать как справку; если нет — оставить пустыми.

## Приоритет критериев рейтинга

По решению пользователя, общий километраж трасс сохраняется только как справочная информация. Если официальный источник не приводит показатель, он остаётся пустым; собирать его любой ценой или оценивать приблизительно не нужно. В ранжировании курортов километраж не используется.

Для прототипа рейтинг должен сосредоточиться на критериях выбора, обсуждавшихся для конструктора поездок:
1. Погодные условия на выбранный месяц/дату — прогноз, если он доступен, иначе месячная климатическая оценка с оговоркой о неопределённости.
2. Совместимость уровня катания пользователя с доступными трассами курорта.
3. Совпадение выбранного вида катания/активности (например, трассовое катание, фрирайд, фристайл) с подтверждённой инфраструктурой курорта.

По ранее согласованному правилу одного совпадения с обязательным критерием достаточно, а курорт, который совпадает сразу с несколькими, поднимается выше.

Дополнительные характеристики вроде общей длины трасс могут отображаться в карточке курорта для контекста, но не менять его место в рейтинге. Методика соответствия уровня катания и погодных предпочтений ещё подлежит отдельному согласованию до реализации формулы рейтинга.


## Сбор уровней трасс и активностей

В `piste_difficulty_categories` сохраняем термины источника без самостоятельного перевода в уровни «новичок / средний / профи». У разных курортов эти категории не совпадают. Для рейтинга потребуется отдельно согласовать таблицу соответствия категориям пользователя. На 13.10.2026 поле заполнено источником для 30 из 30 активных курортов; у двух указано лишь общее описание «разного уровня сложности», без категорий по трассам.

Подтверждённые примеры первичных источников: Роза Хутор — четыре текстовые категории; Архыз — цветовая легенда; Эльбрус — лёгкая/средняя/сложная; Мамисон — лёгкая/средняя/сложная/очень сложная; Телецкий — зелёные/синие/красные. Для Домбая пока подтверждён лишь учебный склон. По Абзаково категории сложности перенесены с цветовой легенды официальной карты курорта; происхождение карты подтверждено пользователем.

`activity_tags` содержит только заявленные источником активности. `freeride` особенно важно отличать от обычного катания по трассам: не добавлять этот тег на основании рельефа или предположения. Сведения и схемы, предоставленные пользователем по Чегету и Цея, приняты как проверенные для прототипа. Для Морозной горы предоставленная схема подтверждает расположение объектов, но не содержит легенды сложности; более поздние уточнения можно внести в итоговом проекте.

Пробелы и ограничения по сложности: по Абзаково цветовые категории взяты с официальной карты, источник которой подтвердил пользователь; дата карты не видна, актуальность схемы для текущего сезона нужно проверить. Для Аджигардака использована официальная карта сезона 2019/20, для Завьялихи и Абзаково — официальные карты без видимой даты; пользователь уточнил, что изображения взяты с сайтов курортов. Источник теперь отмечен как проверенный, но актуальность схем на текущий сезон требует отдельной сверки. По Чегету и Цея предоставленные пользователем схемы и сведения приняты как проверенные для прототипа. По Морозной горе принята схема расположения объектов; она не подтверждает цвета сложности. Любые неточности в этих исходных данных можно исправить при подготовке итогового проекта. У Горы Белой источник разъясняет часть цветовых категорий, но не подтверждает полный перечень. Справочные километражи на рейтинг не влияют. Схема сопоставления сложности согласована: исходные формулировки сохраняются, а для рейтинга приводятся к трём уровням. Далее — завершить сбор недостающих категорий и активностей, затем перейти к погодным данным и расчёту рейтинга.









### Мраткино — проверка классификации трасс

По предоставленной информации для прототипа приняты зелёная, синяя и красная категории. Перечислены пять трасс южного склона (одна зелёная, три синие, одна красная) и три трассы северного склона (одна синяя, две красные). Длины и перепады сохранены только как справочные сведения. Данные считаются рабочими для прототипа; сезонные изменения можно поправить в итоговом проекте.




### Морозная гора и Цей — новые схемы

По предоставленной схеме Морозной горы видны трассы №1–7, отдельная детская трасса, подъёмники и строящаяся трасса. Дата и легенда сложности на изображении не видны; цвета линий не используются для классификации. Расположение объектов принято как рабочая информация для прототипа.

По Цейскому курорту предоставленный текст из вторичных источников указывает 2 чёрные, 3 красные и 2 синие трассы. Приложенная схема использует более общие обозначения: низкая и высокая сложность, отдельно фрирайд-маршруты. Эти описания могут быть совместимы, но схема не позволяет разложить уровни по цветам и номерам трасс. Информация из предоставленного пользователем текста принимается как проверенная для прототипа; для расчёта уровни приводятся к трём стандартным категориям.



### Нормализация сложности для рейтинга

В поле piste_difficulty_categories сохраняются исходные формулировки курорта без замены. В новом поле piste_levels_normalized категории приводятся для рейтинга к трём уровням: beginner (новичок), intermediate (средний), pro (профи). Нормализуем по смыслу подписи легенды, а не по универсальному цвету: beginner/training/easy/low/для начинающих → beginner; medium/средний → intermediate; high/advanced/сложный/для профи → pro. Если карта использует цвет, ориентируемся на её собственную легенду: один и тот же цвет в разных курортах может означать разные уровни. При четырёх уровнях beginner и low объединяются в beginner; high и самый высокий уровень — в pro. Если написано лишь «разной/различной сложности» без конкретных категорий, нормализация остаётся пустой до появления деталей.

Информация, которую пользователь прислал из источников или в виде схем, считается проверенной для прототипа и используется в расчётах, даже если позже потребуется поправка. Возможные сезонные изменения и неточности можно уточнить при подготовке итогового коммерческого проекта. Оригинальные категории и источник сохраняются для последующей корректировки.




Для Морозной горы применяется уточнение пользователя: синяя трасса относится к лёгким (beginner), остальные — к средним (intermediate); чёрные линии на схеме обозначают фрирайд-маршруты и не учитываются как уровень сложности. Это курортное уточнение имеет приоритет над общим сопоставлением цветов.


Для Шерегеша легенда карты даёт четыре уровня: начинающие и низкий сведены к beginner, средний — к intermediate, высокий — к pro. Для Сорочан: зелёная для начинающих и синяя лёгкая — beginner, красная средняя — intermediate, чёрная высокая — pro; отдельно отмечена тюбинговая трасса. Схемы предоставлены пользователем и считаются проверенными для прототипа.


## Таблица цен `resort_prices.csv`

Одна строка — один опубликованный тариф/вариант цены; связь с основной таблицей через `resort_id`. Собираем все опубликованные цены категорий, необходимых конструктору: ски-пасс, прокат, размещение на территории курорта, трансфер с пометкой, кто его предоставляет. Для внешнего трансфера указывать стороннего оператора и не смешивать его с услугами курорта.

Поля: `price_id`, `resort_id`, `service_category`, `service_name`, `provider_relation`, `provider_name`, `tariff_name`, `visitor_category`, `equipment_or_room_type`, `valid_from`, `valid_to`, `season`, `price_amount`, `currency`, `pricing_unit`, `conditions`, `source_url`, `checked_at`, `data_status`, `notes`.

`service_category`: `ski_pass`, `equipment_rental`, `accommodation`, `transfer`. `provider_relation`: `resort_provided` или `third_party_separate`. Для тарифа записывать возраст/категорию гостя, сектор, срок действия, комплект проката или тип размещения — в зависимости от категории и данных источника. Цену не выводить самостоятельно, если её нет в источнике. Тарифы с разными периодами/единицами/условиями нельзя напрямую сравнивать; эти параметры и дату действия сохранять обязательно.

## Приоритет и допущения по пользовательским материалам

По последнему решению пользователя все предоставленные им схемы и описания трасс считаются актуальными и проверенными для прототипа. Не маркировать их как сомнительные только из-за даты изображения. Координаты из ссылок Яндекс.Карт, присланных пользователем, также считаются им проверенными; координата остаётся точкой курорта/района, не конкретного склона. Координатные кандидаты Open-Meteo/OSM, полученные аналитиком, не считать пользовательски проверенными.

В основную рабочую выборку включать заполненные обязательные поля; незаполненные необязательные характеристики отложить. Общий километраж трасс показывать только как дополнительную справку, не как основной критерий.
