# Сбор прогноза погоды

## Что делает скрипт

`scripts/collect_weather_forecast.py` читает координаты из `data/reference/resort_data_collection_template.csv`, пропускает строки со статусом `excluded` и отправляет широты и долготы действующих курортов в Open-Meteo Forecast API. Координаты передаются одним запросом списками; API возвращает отдельный ответ для каждой точки.

Запрашиваются дневные показатели на срок до 16 дней:

- максимум и минимум температуры на высоте 2 м;
- сумма снегопада и осадков;
- максимальная скорость ветра на высоте 10 м;
- код погоды WMO.

Команда запуска:

```powershell
python scripts\collect_weather_forecast.py --days 16
```

`--days` можно задать от 1 до 16. Скрипт сохраняет полный ответ API вместе с URL, порядком курортов и временем запроса в `data/raw/weather_forecasts/`. Дневные записи для анализа записываются в `data/processed/weather_forecast_daily.csv`.

## Как читать результат

- `latitude_input` и `longitude_input` — приблизительные координаты курорта из нашей таблицы.
- `latitude_api_grid`, `longitude_api_grid` и `elevation_api_m` — ячейка и высота модели, по которой API подготовил погоду. Они могут отличаться от входной точки.
- `retrieved_at_utc` показывает, когда был получен ответ; погода привязана к местной дате курорта и его часовому поясу.
- Пропущенное значение не следует заменять нулём: это означает, что API не вернул показатель для этой точки/даты.

Текущий запуск вернул HTTP 200 для 30 действующих курортов и создал 480 дневных строк на 16 дней. Прогноз — это не климатическая норма: для дат за пределами горизонта до 16 дней нужен отдельный расчёт приблизительной месячной погоды по историческим данным. Месячная историческая оценка подключена отдельным скриптом и описана ниже.

## Месячная историческая оценка для дальних дат

Скрипт `scripts/build_monthly_weather_climatology.py` запрашивает дневные ERA5 данные для координат действующих курортов за указанный период и агрегирует их по календарным месяцам. Первый набор рассчитан за 2016–2025 годы. Итог находится в `data/processed/weather_monthly_climatology.csv`; версия с датой формирования сохраняется рядом, а исходный ответ каждого курорта — в отдельной папке `data/raw/historical_weather/`.

В итоговой таблице 360 строк: 30 курортов × 12 месяцев. Месячные суммы снегопада и осадков сначала считаются отдельно за каждый год, затем усредняются за период. Температурные и ветровые показатели являются средними дневных значений внутри месяца, усреднёнными по годам; также рассчитывается среднее число дней со снегопадом.

Запуск первоначального периода:

```powershell
python scripts\build_monthly_weather_climatology.py
```

Для ежегодного обновления следует выбрать последние 10 полных лет и дождаться появления архивных данных за предыдущий год. Например, после поступления полных данных за 2026 год:

```powershell
python scripts\build_monthly_weather_climatology.py --start-date 2017-01-01 --end-date 2026-12-31
```

Старые исходные ответы и версии итоговой таблицы сохраняются, чтобы период и происхождение каждого набора можно было проверить. При HTTP 429 или сетевом сбое скрипт создаёт файл с пометкой `incomplete` и не заменяет им основной `weather_monthly_climatology.csv`; повторный запуск с `--resume-dir` использует уже сохранённые успешные ответы.

### Оговорка для прототипа

Месячные значения — это **историческая оценка типичной погоды за 2016–2025 годы**, а не прогноз погоды на будущую поездку и не гарантия условий в конкретный год. Межгодовые различия сглаживаются усреднением. Данные ERA5 являются реанализом метеоданных с модельной сеткой около 25 км; в горном рельефе локальная погода на курорте и склонах может отличаться. Координаты курортов также приблизительные. API возвращает фактическую ячейку сетки и высоту модели; они сохранены отдельно от исходных координат.

В конструкторе такую оценку нужно явно обозначать как «Историческая оценка (2016–2025)», отдельно от прогноза. Для прототипа это годится для сравнения курортов по месяцам, но не для точного обещания погоды. По мере накопления новых полных лет набор следует пересчитывать примерно раз в год; также пересчитывать его при изменении координат или источника данных.

## Ограничения использования

Open-Meteo указывает, что Forecast API принимает координаты, а прогноз можно запросить максимум на 16 дней. Открытый бесплатный доступ предназначен для некоммерческого использования и прототипирования; для коммерческого продукта требуется подходящая лицензия/план. При распространении данных требуется атрибуция Open-Meteo и указание изменений.

Источники: [документация Forecast API](https://open-meteo.com/en/docs?past_days=1), [документация Historical Weather API](https://open-meteo.com/en/docs/historical-weather-api), [условия и тарифы](https://open-meteo.com/en/pricing).
