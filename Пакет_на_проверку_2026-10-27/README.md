# Горнолыжные курорты — пакет на проверку

Пакет содержит Power BI-отчёт, чистовую Jupyter-тетрадку, исходные таблицы и подготовленные CSV для загрузки в Power BI. Исходные файлы проекта не изменялись.

## Состав пакета

- `powerbi/Горнолыжки.pbix` — отчёт Power BI с тремя страницами: рейтинг курортов, аэропорты и трансфер, профиль курорта.
- `notebooks/Подготовка_данных_курортов.ipynb` — тетрадка, которая собирает месячный рейтинг и экспортирует таблицы для Power BI.
- `data/processed/` — мастер-данные, погодная климатология, результаты расчёта и CSV, загружаемые в отчёт.
- `data/reference/` — справочники тарифов, курортов, проверенных фактов, инвентаря подъёмников и вариантов трансфера.
- `docs/` — описание проекта и схемы сбора данных.
- `requirements.txt` — Python-зависимости для тетрадки.

## Быстрый просмотр отчёта

Откройте `powerbi/Горнолыжки.pbix` в Power BI Desktop. В модель включены четыре таблицы:

1. `powerbi_monthly_ranking.csv` — 210 строк рейтинга: 30 курортов × 7 месяцев сезона.
2. `powerbi_resorts_with_transfers.csv` — 30 строк, по одной на курорт, с характеристиками и сводкой трансферов.
3. `powerbi_airport_routes_top3.csv` — до трёх аэропортов на курорт, всего 90 строк.
4. `powerbi_transfer_options.csv` — 43 варианта трансфера.

Страницы отчёта показывают помесячный рейтинг, аэропорты и время в пути, варианты трансфера, а также профиль выбранного курорта. Для навигации используйте вкладки страниц внизу отчёта.

### Обновление данных в Power BI

При обычном открытии PBIX уже сохранённая модель отображается без CSV. Чтобы обновлять её из файлов пакета на другом компьютере, откройте **Преобразование данных → Параметры источника данных** и укажите соответствующие CSV из `data/processed/`. Для таблицы вариантов трансфера укажите `data/processed/powerbi_transfer_options.csv`. После смены путей нажмите **Закрыть и применить**, затем обновите отчёт.

Если Power BI не предлагает сменить путь для конкретного запроса, откройте его в Power Query и поправьте путь в шаге **Источник**. Визуальные поля и пользовательские преобразования хранятся в PBIX; сами CSV остаются в исходной структуре пакета.

## Запуск тетрадки

1. Установите Python 3.10 или новее.
2. Установите зависимости из папки пакета:

   ```bash
   python -m pip install -r requirements.txt
   ```

3. Откройте `notebooks/Подготовка_данных_курортов.ipynb` в Jupyter Notebook или JupyterLab.
4. Выполните ячейки сверху вниз (**Run All**).

Тетрадка сама находит корень пакета по папкам `data/` и `notebooks/`; исходный путь на компьютере автора не нужен. При успешном запуске она пересоздаёт файлы рейтинга и Power BI-экспорты в `data/processed/`.

## Какие входные файлы использует тетрадка

Все семь файлов входят в пакет:

| Файл | Для чего нужен |
|---|---|
| `data/processed/resort_data_master.csv` | Мастер-таблица курортов и инфраструктурные характеристики |
| `data/processed/weather_monthly_climatology.csv` | Погодные среднемесячные значения |
| `data/reference/resort_prices.csv` | Тарифы ски-пассов, из которых вычисляется цена за день |
| `data/processed/powerbi_daily_price_additions.csv` | Вручную внесённые дневные цены; при наличии заменяют рассчитанные по тарифам |
| `data/processed/resort_airport_routes_top3.csv` | Три ближайших аэропортных маршрута-кандидата на курорт |
| `data/processed/resort_best_airport_by_road.csv` | Выбранный аэропорт по времени в пути |
| `data/reference/resort_transfer_options.csv` | Собранные варианты трансфера и тарифы |

Тетрадка формирует `resort_monthly_ranking.csv`, `powerbi_monthly_ranking.csv`, `powerbi_resorts.csv`, `powerbi_airport_routes_top3.csv`, `powerbi_resorts_with_transfers.csv`, `powerbi_transfer_options.csv` и `resort_transfer_summary.csv`.

## Логика рейтинга

- Сезон: ноябрь–май (январь–май, ноябрь, декабрь); остальные месяцы исключены.
- Погодный балл — среднее трёх равновесных компонентов: комфорт температуры, месячный снегопад и число снежных дней.
- Максимальная температура по баллу приходится на диапазон от −7 до −5 °C; за его пределами оценка снижается.
- Снегопад и снежные дни нормируются по общим максимумам среди курортов и месяцев сезона.
- Инфраструктурный балл — среднее нормированных оценок длины трасс, числа подъёмников и диапазона высот.
- Цена ски-пасса за день получается делением цены тарифа на число дней катания для распознанных взрослых/общих тарифов. Часовые, подъёмные и сезонные тарифы не переводятся в цену за день. Вручную внесённая дневная цена заменяет рассчитанную для того же курорта.
- Более низкая дневная цена даёт более высокий ценовой балл.
- Общий балл — среднее доступных баллов погоды, инфраструктуры и цены. Отсутствующая цена не подставляется; число учтённых критериев выводится в `criteria_used_count`.

## Важное замечание о погоде

Сейчас тетрадка использует `weather_monthly_climatology.csv` и присваивает погодным строкам `weather_basis = climatology`. Она **не смешивает** ежедневный прогноз с климатической статистикой. Это фактическое поведение текущей чистовой версии. Если для проверки требуется именно комбинация прогноза на доступные даты и климатологии на остальные, потребуется отдельное изменение расчёта и подготовка соответствующей таблицы.

## Интерпретация и ограничения

- Значения OpenSkiData и другие собранные характеристики включены как рабочие данные для сравнения; это не гарантия полной или официальной точности.
- Цены трансферов могут быть ориентировочными, сезонными или указаны за автомобиль либо за пассажира. Смотрите `fare_unit` и `data_status`.
- Ближайший аэропорт по расстоянию не обязательно имеет регулярное сообщение. В таблице маршрутов есть `airport_scheduled_service`.
- Время поездки — оценка автомобильного маршрута по дорожной сети, без учёта сезонных закрытий, пробок и расписаний транспорта.
- Ценовые баллы зависят от имеющихся тарифов и введённых дневных цен; отсутствие тарифа не означает бесплатный проезд.
